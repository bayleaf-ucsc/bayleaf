      Usage
      What can BayLeaf see?

      Your conversations and files stay in this browser. Each model request is encrypted here, to an enclave whose hardware attestation and published code this page verified. BayLeaf relays ciphertext and sees who you are (your key, or your IP under Campus Pass), when you send, how many bytes, and which model ran. It cannot read prompts, replies or the file contents your agent reads. The agent's tools run in this page, not on a server. The weakest link is this page itself.

      The bayleaf command can send data outside the pouch; Pouch asks you every time. Web search and fetch, the sandbox VM and inboxes are plaintext to BayLeaf (not logged, by policy) and some reach third parties. Each request shows exactly what goes and who can see it, and a denial sends nothing.

      What each task can see

      Every task works in a namespace: only the folders bound into it exist for it. The agent sees the tree below; each run call and subagent gets a narrower one, reached over the 9P file protocol, and the agent can read the same list at /task/<id>/ns. Namespaces limit files, not the network: leaving the pouch is still governed by this page's Content-Security-Policy and your per-session grants.

      Check this page

      This page talks only to api.bayleaf.dev, and to its own origin to download the optional Local model: its Content-Security-Policy (connect-src) says so, and the browser enforces it. The Local model's files are checked against a manifest whose SHA-256 is built into this page; downloading them tells the host that this browser fetched the model, nothing more. Local turns send nothing.

      Build __BUILD_ID__. A page cannot vouch for its own hash: the one below is what this page's code checked when it kept the copy. Save the page, then compare its hash with SHA256SUMS from the release: shasum -a 256 pouch.html

      This copy

      The hosted page keeps an offline copy: its files are checked against SHA256SUMS before they are kept, it loads with no network, and it changes only when you press Update, which checks the new files the same way. One part updates without asking: browsers replace sw.js, the small script that serves the copy, whenever the server's bytes change. It only serves the kept files; the Service worker line says whether it is the one this build expects.

      Settings

      New message display

      Display preferences only, saved in this browser. They do not enable reasoning or change model reasoning effort. Existing messages keep their own open/closed state while streaming. Erase all resets these preferences.

      Sending while Pouch works

      Steer: Pouch reads your message after its current step, in the same turn. Queue: it waits until the whole turn ends, then starts the next turn. Alt+Enter (Option+Enter on a Mac) does the other one for a single message; the arrow next to Stop offers both. Saved in this browser.

      Offline copy and updates

      Pouch changes only when you press Update.

      Model selection

      The model below your message applies to your next user turn. Running work, including subagents, keeps the model it started with.

      Local model

      Checking...

      Local runs a small model (about 1.1 GB, downloaded once and checked part by part) on this device's GPU. Nothing you type is sent. It suits looking around a workspace and small, literal edits; use Sealed for bigger work. A saved copy of the models folder (or the original model files) can be loaded without the network. Erase all removes it too.
