# Pouch user journeys

A story map for design and testing. The backbone runs left to right as one visit; each
column lists stories under it, marked **ok** (built and tested), **gap** (missing),
or **?** (built, untested). Tests and design changes should cite story IDs.

## People

| Persona | Setting | What they need most |
|---|---|---|
| **Lab** – a student on a borrowed lab computer | private window, campus network, no key, 40 minutes | bring files in fast, get them out before leaving, leave nothing behind |
| **Phone** – a student on their own phone | mobile browser, signed in with a claimed key | small edits and questions on files they already have; tapping, not dragging |
| **Desk** – a TA or researcher on their own laptop | Chromium, a project folder mounted read-write | the agent doing real multi-file work, and seeing exactly what changed before trusting it |
| **Auditor** – someone checking BayLeaf's claims | any browser, devtools open | proof the page is static, talks only to `api.bayleaf.dev`, and sends ciphertext |
| **Commuter** – a student on a train or a flaky campus link | Pouch already open (or a saved copy), network drops mid-session | keep reading, editing and transforming files offline; never lose work; know exactly what needs the network |
| **Analyst** – a staff member with an exported dataset | a messy export from another system (quoted CSV with commas and line breaks inside fields, nested JSON) | a correct transformation they can check, rerun and hand on, without uploading the raw data anywhere |
| **Agent** – the model inside Pouch | system prompt, four tools, a simulated shell | to know where files are and what the shell can do, and to get errors it can recover from |

## Backbone

`Arrive → Trust → Bring files in → Direct the agent → Review → Take files out → Leave`

- D11 ok: your messages are tinted bubbles on the right, replies full-width markdown, tool calls small grey pills, thinking muted. - D12 ok: Revert to here forks the conversation just after a message (pi-durable `fork`, in the session's own database) and points the session at the fork, so the model never sees the later turns. A confirm sheet counts the messages that leave and offers "Also undo changes to N files made after this message" (checked, files listed). The revert is undoable until the next revert, from an inline "Reverted to <time>. Undo" and the session menu: it points back to the earlier conversation and puts the files back as they were at the revert, warning if they changed since and if you sent messages since. Disabled while a run is active and for legacy sessions. Deleting the session erases every fork and the kept file bytes. (t10c: model recall excludes turn 2/3 words, undo restores transcript and file, marker scan empty after delete)
- D20 ok: the composer is one rounded, elevated card, after OpenChamber's: an activity tray on top, the input, and a bottom row with verbs on the left (Attach, a shield that opens a popover with this session's lane, "Sealed: encrypted to the enclave", and its egress grants with Revoke, and a compact Usage count that opens the Usage panel) and settings on the right (the model picker with a lane icon, and an icon-only Send that becomes Stop). 44px targets on desktop and touch; no overflow at 390px. - D21 ok: the activity tray shows, only while something is active, running subagents (name, task excerpt, "subagent", elapsed, Stop), an in-flight `run` (script, elapsed, Stop, which stops that one call and lets the model carry on), approvals waiting for you (with the subagent's name), and a queued message (Cancel puts it back in the box). Header "Running: N" (plus waiting and queued counts), a collapse chevron, and Stop all when two or more can stop. Elapsed ticks each second only while the tray is open and the page visible. (t16: both kinds listed, ticking, collapse, Stop all in under 0.1 s against a 5 s run, single run Stop reports "Stopped." to the model; t12f: tray empty after a reload, since an interrupted child is not running)

Enter or a tap runs a command; Tab completes its name; a `/` followed by anything else (`/work/notes is a folder`) is sent as text. Listbox and option roles, aria-activedescendant, aria-expanded; keyboard (arrows, Enter, Tab, Esc) and touch (44px options; the input keeps focus). (t16 desktop and 390px)

Beyond the pouch, through the `bayleaf` CLI (each outbound action asks first; see D10):
- D13 ok: research on the web: the agent searches and fetches pages and saves notes or sources into /work; each query and URL is approved, and the transcript marks what left the pouch. (t10b: search with deny/allow once/allow for session)
- D14 ?: check BayLeaf inboxes for new messages ("anything new since yesterday?"): the agent lists inboxes and summarizes unread messages. Listing and reading exist in the CLI (live-tested in Node with no inboxes); untested in the browser, and "new since last check" needs a remembered per-inbox marker (gap).
- D15 ok: background subagents: "look into related work on X while we keep going": the agent hands a self-contained task to a child conversation (`subagent` tool, `src/subagents.js`) that runs in the background (web research through the `bayleaf` CLI, or exploring a codebase in /work or a mounted folder) while the main conversation stays responsive. When the child finishes, its report joins the main conversation as a follow-up (the parent gets one turn to use it); a stopped child is noted without spending a request. A reload never spends requests by itself: a running child (or parent run) is stopped and marked interrupted, the parent is told without a request, and one click on Resume continues it; reports post once (request ids). (Background *bash* jobs were considered and dropped: just-bash runs on the page's main thread, so only network-bound work interleaves, and that work is what subagents do.) (t11 with glm-5-3: parent answered while child ran, exactly one report, summary file written, parent used report next turn; node test/subagents-node.mjs with a scripted fake model; t12: 0 Sealed POSTs across 3 reloads after a finished turn, mid-run, and with a child running)
- D16 ok: subagents are visible and controllable: each child shows as a card at the spawn point with its task, status, time, request count, live read-only transcript, Stop, Message, and the files it changed (Diff, Undo); the report renders in the transcript; the sidebar badges sessions with running children; approvals from a child say "Subagent <name> wants to ..."; children spend the daily allowance (Usage panel notes running ones; spawning when 15 or fewer are left warns), cannot spawn their own children, run at most three at a time, and are erased with the session. (t11: deny/allow from a child, Stop button, 390px card without overflow, marker scan empty after delete; cap and no-nesting only in the node test; no real-phone session)
- D18 ok: the agent runs JavaScript when bash is not enough: a `run` tool (`src/run.js`, engine in `src/run/`, ported from experiments/quickjs) executes a script (`code`, or `path` of a .js file) in QuickJS (WebAssembly) inside a throwaway `blob:` worker that sees only a snapshot of the files it names (paths, folders, globs; default the script's folder, or /work for inline code; 500 files, 16 MB, 4 MB per file, refused with a clear message), with no network, credentials or storage access. Output (status, exit code, stdout/stderr, at most 20 named changes per list) comes back to the model; proposed changes go through the same recording proxy (listed under the turn, Diff, Undo); a file changed meanwhile is a conflict, reported and not applied; a timed-out, OOM or stopped run applies nothing. Limits 5 s, 64 MiB, 64 KiB output, lowerable, not raisable (schema). Stop terminates the worker. A `.js` file's menu has Run script (same tool, no model; changes recorded under the latest message). CSP adds exactly `'wasm-unsafe-eval'` and `worker-src blob:`. Bundle +1021 KiB raw, +283 KiB gzip. (t13, scripted fake model, 23 checks: hello, files in/out, path and globs, conflict, timeout 124, OOM 137, truncation, exit code, guest error, Stop in <1 s, no fetch/XHR/WebSocket/indexedDB/timers in the guest, no requests beyond api.bayleaf.dev, both caps, review Undo all; guest `eval` works inside QuickJS, by design)
- D19 ok: Analyst journey: attach an external export (drag onto the chat or Files), ask for a transformation that defeats awk/jq (a quoted CSV whose fields contain commas, doubled quotes and line breaks, `$85,000` salaries, stray-cased codes, `n/a`/empty salaries and unknown codes, joined with a nested JSON lookup, aggregated with medians), and get a correct output file plus the script that produced it saved in /work so the user can rerun or hand it on. The raw data never leaves the browser except inside sealed model requests, and only the parts the agent reads. (t14 with glm-5-3, 8 model requests, 19 s: read both, wrote /work/build_report.js with its own RFC 4180 parser, one failed run fixed by an edit, report.csv equal to Python's `csv` + `statistics.median` for all 7 departments; Run script from the file menu reproduced it byte for byte; both files listed under the turn. The agent read the whole CSV into context with `read`, so 'only the parts it reads' was all of it here)

### 8. Work offline
- F1 ok: the network drops mid-session: files, editor, review, archive import/export and `run` keep working; the shield turns grey, the status line and Send's title say "Offline: the model is unreachable" (not "verification failed"), Send and Enter are refused, the draft stays, and an in-flight turn is aborted at once and shown as "Connection lost". Detection: online/offline events, plus a network-like request failure followed by a failed re-check of `/sealed/models`. (t15 with a scripted fake model and `context.setOffline`: turn ends in ~0.6 s; upload, Run script, change listed, Diff, Undo, editor save, .zip download and unpack all offline; captive-portal case via aborted routes with navigator.onLine true. Not live-tested against a real Sealed stream; subagent runs are not aborted explicitly)
- F2 ok: the network comes back: Pouch notices (online event, or the 15 s re-check), re-verifies the enclave, re-enables sending and refreshes usage, without a reload; the draft is still there and sends. (t15)
- F3 ok (hosted, Chromium; 2026-10-30): start Pouch with no network. Decided: the hosted page keeps an offline copy through a service worker with explicit updates only (README "Install and the offline copy"). sw.js is a separate same-origin file (CSP `worker-src 'self' blob:`), tiny, and only serves the shell from a cache named by the HTML's SHA-256; the page pins that copy after checking every file against SHA256SUMS, shows which build runs (label, pinned hash, published hash, whether the served sw.js is the expected one), and swaps it only when the user presses Update, after the same check. Offline reload loads the copy; `/work` persists (OPFS works for the hosted origin). A saved `pouch.html` from `file://` is unchanged: it loads offline, but Chromium (SecurityError) and WebKit (UnknownError) refuse OPFS to file:// pages, so `/work` is memory only (tagged) and lost on reload; IndexedDB persists. Sending Sealed still needs the network (attestation bundle). (test/pwa-browser.mjs 17/17 in Chromium; t15 for file://; WebKit gap under F5; Firefox untested)
- F4 built (t17): an agent without the network: "Local: LFM3 1.7B (on this device)" in the picker (with --with-models builds and WebGPU), labeled "On this device: nothing sent"; the ~1.1 GB model is downloaded once on request from Pouch's own origin, verified part by part, kept in Cache Storage, and answers and runs tools offline. Switching lanes is explicit, never automatic; a hint suggests Sealed at the step cap, after two failed edits, past 3 files or past ~4k tokens.
- F5 ok in Chromium, gap elsewhere: install Pouch as an app. Manifest (`/`, standalone, BayLeaf icons incl. maskable and apple-touch-icon) passes Chromium's installability check with no errors; Settings and the trust panel offer "Install app" where the browser fires `beforeinstallprompt` (Chromium), otherwise the browser's own Install / Add to Home Screen applies, and the app works the same uninstalled (Firefox desktop has no install). Update notice names both short hashes, Later changes nothing, Update verifies then reloads, a tampered release is refused with the mismatching hashes and the old copy keeps running; Uninstall offline copy and Erase all unregister the worker and delete the copy; persistent storage is requested at boot and on `appinstalled`, and its state shown. (pwa-browser.mjs; screenshots /tmp/pouch-qa/shots/pwa-*.png) Gaps: Playwright WebKit pins the copy but its worker fails offline in this harness (`FetchEvent.respondWith ... Load failed`), while a bare page with the same sw.js passes; check real Safari/iOS. Android install, iOS Add to Home Screen, Firefox and the deployed Cloudflare headers (manifest content type) are untested.
